# CairnJS Project Governance

This document describes the governance model, leadership structure, decision-making processes, and contributor rights for the **CairnJS** open-source project.

---

## 🏛️ Governance Principles

CairnJS is governed by open, collaborative, and meritocratic principles:

1. **Transparency**: Discussions, roadmaps, RFCs, and release plans are conducted openly on GitHub.
2. **Quality & Zero-Dependencies**: Architectural integrity, zero third-party lock-in, and 100% test coverage take precedence over rapid bloat.
3. **Inclusivity**: Everyone is encouraged to participate and contribute regardless of background.

---

## 👥 Roles & Responsibilities

### 1. Project Lead & Maintainers
- **Responsibilities**: Overall vision, architecture direction, final approval on major breaking changes, NPM package releases, security disclosures, and repository administration.

### 2. Core Collaborators
- **Responsibilities**: Reviewing Pull Requests, triaging issues, maintaining test suites, authoring docs/examples, and participating in RFC discussions.
- **Appointment**: Active contributors who demonstrate consistent high-quality contributions and adhere to the [Code of Conduct](CODE_OF_CONDUCT.md) may be invited as Core Collaborators.

### 3. Contributors
- **Responsibilities**: Submitting bug fixes, feature proposals, test improvements, and documentation enhancements via Pull Requests.

---

## 🗳️ Decision-Making Process & RFCs

1. **Bug Fixes & Minor Improvements**:
   - Approved and merged via standard Pull Request review by at least one maintainer or core collaborator.
2. **Major Architectural Changes & New Modules**:
   - Must be proposed as an **RFC (Request for Comments)** via GitHub Discussions / Issues.
   - Requires community review period (minimum 7 days) and consensus among maintainers.
3. **Releases & Versioning**:
   - Follows [Semantic Versioning 2.0.0](https://semver.org/).
   - `MAJOR`: Breaking architectural API changes.
   - `MINOR`: Backwards-compatible new features (e.g. `1.2.0`).
   - `PATCH`: Backwards-compatible bug and security fixes.
